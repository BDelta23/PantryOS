## Open blockers

- Home Assistant uses the PantryOS Core API setup path now, and diagnostics redaction helpers exist, but full HA runtime tests, coordinator/push subscription, reconfigure/reauth, service lifecycle, and recovery behavior are still pending.
- Browser compatibility routes now require same-site browser session cookies, per-session CSRF on unsafe methods, and same-origin browser requests. Remaining browser security gaps are token setup UX polish, persistent sessions across process restart, and HTTPS/Secure-cookie deployment mode. API JSON body, receipt upload MIME/size/path policies, and receipt upload/extract rate limits now exist for the implemented local text/CSV receipt path.
- Browser visual automation is not yet evidenced in this Windows/UNC Codex environment because Browser node_repl setup failed with `CreateProcessWithLogonW failed: 267`; HTTP workflow smoke and static regression tests are present.
- OpenAPI 3.1 is served from authenticated `GET /api/v1/openapi.json` and route/security/problem shape is tested; richer per-resource schema precision and final release doc review remain pending.
- Events are persisted and authenticated `/api/v1/events` now returns an SSE-compatible hello/recent-event replay, but long-lived push fanout and HA coordinator stream consumption are still pending.
- Advanced product/location/recipe UI, receipt image/OCR ingestion, receipt upload retention, camera barcode feature detection, and richer price anomaly UI are still incomplete.
- CLI doctor/backup/restore/import dry-run operations exist and are locally/container smoke-tested; upload-file-inclusive backups and migration-failure recovery still need release proof.
- Docker now starts through a root entrypoint only long enough to repair `/app/data` ownership, then runs PantryOS as UID/GID `10001`; read-only root filesystem, upload/backup path allowlists, and broader image hardening remain pending.
- Completion acceptance criteria are not fully evidenced.
